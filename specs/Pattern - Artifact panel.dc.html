Two modes

The body never knows the mode.

The same artifact is reviewed in the console and shown in a proposal. One frame serves both: the mode swaps the header-right, the status strip and the footer — and nothing else. Body markup, geometry and type are identical, so a body written once renders in every surface.

What the mode changes
Header rightReview — ⤢ expand + ✕ close, because the panel is a workspace. Read — a leading glyph tile, a sub line naming the kind of work, and a mono position counter, because the artifact is one of a set being shown.
Status stripReview only. The strip reports live job state; a proposal artifact has no job yet, so there is no state to report and no strip to draw.
FooterReview — the decision bar: owner meta left, verbs right. Read — the provenance bar: origin left, the promise right ("Held for you on signing"). Same 11px rhythm, no buttons.
What it never changes
Panel geometry and radius · body padding · every type size inside the body · the payload contract. A body is authored once against its typed payload and is mode-blind — read mode simply mounts it with edit affordances off: no hover "+", no tracked changes, no image-slot drop, no cycler arrows. Nothing in the body may branch on mode. If a surface needs different content, it needs a different payload — not a different body.
reviewChat panel · expanded viewer · Work queue row · anywhere a job is decided. Editable, stateful, verbs present.
readProposal "What we deliver" stage · Performance outcome chains · anything shown to someone who cannot act on it. Same body, no chrome, no verbs.
retype ruleart/page summarises a change — it needs a prior state to diff, which a proposal has not got. A page shown before any site exists is the page itself, so it is art/visual with a browser-chrome media frame. Never add a preview to art/page to make read mode work.
The seven bodies

Typed payloads, never free-form.

art/postSocial content as the platform's own card — avatar, handle line, text, media. Approve & release.
art/articleA reading page where everything is directly editable — click and type, no editor chrome; clicking away commits a TRACKED CHANGE (struck deletions, green-wash insertions, "Your change" + Keep / Undo). Hover shows one quiet "+" to add blocks. Approve & publish.
art/pageWebsite work: plain-language summary of changes + a quiet tally (+14 −9 · lines changed · 2 files) — never code, never a preview. Committing plays the deploy theater: dual-hex spinner, Build · Deploy · Verify phase rail, then the Live arrival with the URL pill. Commit to staging · Commit & publish.
art/visualMedia frame with a variant cycler ‹ 2 / 4 ›. Use this · Request changes.
art/sequenceOutbound as numbered steps — audience block, merge-field chips, "replies pause the sequence". Approve & send.
art/planJob list rows with an outcome line. Adjust · Approve plan.
art/doc + ruleReports render as Markdown Kit files; a standing job's rule shows cadence, runs, and origin. Unrecognised payloads degrade to art/doc — never broken, never free-form HTML.
The frame

Same chrome, everywhere.

Status strip
Directly under the header: state dot (amber held · gray revising · green approved/live) + one plain-language line — "state · destination on approval" — and the Work queue link. The strip is the only home for state prose; "draft 2 — includes your edits" inside the body is banned. Footer meta carries content facts only.
Panel → Expand
The panel is clamp(320px, 42vw, 460px) beside the chat — one shared width formula so the chat yields exactly panel + gutter; under 1100px it overlays instead of squeezing. The expand glyph grows the same panel in place to full width (prose at 680, post cards at 552, media at 440) ⤢ — the universal viewer for every artifact, opened from anywhere, never navigation. Esc walks back: expanded → panel → chat. Switching screens closes it.
Guidelines

The discipline.

Do
Verbs name the real consequence — publish, deploy, send. No change verb fires blind — Request changes opens the ask popover ("Anything else you’d like to add?") before anything is sent. Every approval confirms "✓ Added to the Work queue — schedule", raises a toast, and writes memory. Secondary actions go ghost; one filled verb per bar. New formats map to one of the seven — extending the taxonomy is a design decision.
Don't
Agents emitting UI — payloads only, rendered through the kit. "Release" or "Submit" as a verb. State prose inside the body. Two filled buttons in one footer. A separate full-screen sheet — the panel IS the viewer.

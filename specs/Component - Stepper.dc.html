Design System
Component · Stepper

How far in, and how far left.

A reading flow with an end. Unlike the rail — which is a set of places you can be — a stepper has an order, a completed half and a destination. It is the proposal's spine, and the only place in the system where progress is a promise.

SECTIONS
Try it
Click a step, or Tab into the rail and press Enter. Steps you have reached are clickable; steps ahead are not — a stepper never lets you skip to an end you have not earned, because the sections build on each other.

The marks

Three, told apart without colour alone.

Done — green-50 fill, green-600 check 3Now — ink-900 fill, white numeral 4Ahead — hollow ink-200 ring, ink-400 numeral
A check replaces the numeral when a step is done — the SHAPE carries the state, so it survives greyscale and colour-blindness. Green appears here because completion is a signal, and this is the one component where green marks something the client did rather than something the engine is doing.

Content rules

Section names, not instructions.

Each step is the section's own name in sentence case — Overview, What we deliver, Cost, Accept & sign — identical to the heading it scrolls to, so the reader never wonders whether they arrived. Never a verb phrase (“Review the cost”), never numbered in the label (the mark carries the number), never truncated with an ellipsis: if a step name does not fit at 224px it is too long a name for a section. Six steps is the practical ceiling; past that the document wants chapters, not steps.
Do
Let the reader go back freely — everything behind them is theirs. Keep the pill as one object that glides. Match the step label to the section heading exactly. Show the count on mobile, where the rail cannot fit.
Don't
Let a step be skipped ahead. Connect the marks with a drawn line — the pill and the order already say it. Use a stepper for a rail (Sidebar) or for a form with one screen. Percentages: a stepper counts sections, and “67% complete” is a number nobody asked for.
